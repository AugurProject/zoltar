How-to guide

Configure the Trading UI

Choose a mode

Without a mode parameter, the UI reads live RPC and wallet state. Add ?simulate=1 to run a browser-local chain. A banner identifies simulation mode.

Set simScenario to choose a starting state.

  • trading-funded starts with one funded market by default.
  • deployed starts with a question ledger with no trading pool.
  • baseline starts without Statoblast or Trading contracts.
  • trading-forked opens the funded market after its universe forks.
  • trading-usdc opens a funded market using six-decimal USDC and separate router approvals.

Set up Trading development to serve the UI locally.

Choose the truthful universe

Choose Yes or No for the displayed Augur v2 fork question. To open that choice directly, add genesis=yes or genesis=no to the URL query, for example ?simulate=1&genesis=yes. The selected universe uses its own REP token and protocol deployment. To change the choice, open Universe under More, follow the selected root's Parent universe link to Augur v2 universe, and open the other child. Returning to the Augur v2 universe clears the previous deployment's market and fork selection.

Select a network and RPC

Open Settings in the header. Choose the RPC network, and optionally enter a Fallback RPC URL and select Save RPC. A custom RPC must use HTTPS, or HTTP on a loopback address, and must serve the selected chain. Trading uses this endpoint for deployment checks even when a wallet is connected. Once connected on the selected chain, the wallet serves ordinary market reads and submits transactions.

The UI then checks the RPC chain and the core contracts, and derives the Trading factory and router addresses for that network. If either is not deployed, the deployment screen opens; Deploy the Trading contracts covers it. The configuration works when the Markets tab opens. The configuration reference describes what the client derives and checks.
