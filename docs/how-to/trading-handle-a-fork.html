How-to guide

Handle a universe fork

A fork closes the parent trading pool for swaps and additions. Holders choose where to migrate their shares.

Check the position

If the question has finalized, redeem winning shares through its question ledger. For an unresolved question, remove parent LP into Yes and No before migrating it.

Migration copies the selected source token’s balance to each child you choose, less any shares you already migrated there. At least one child must receive additional shares. The parent balance stays visible and is permanently locked against outgoing transfers.

Migrate in the UI

  1. Open the market’s Settlement tab and select Migrate.
  2. Choose the Share to migrate (Invalid, Yes, or No), then choose your child universes.
  3. Tick the balance and transfer-lock acknowledgment. Select Migrate to N child universes and confirm.
  4. Check the expected child token IDs and balances. Repeat for each source token you want to migrate.

Choose fork targets

The fork outcome identifies the child universe. Your migrated share keeps its original outcome. Select Invalid or a labeled answer for a categorical fork, or Invalid or an exact tick for a scalar fork.

  • One child with a ledger. Select it directly.
  • One child without a ledger. Activate the child’s security pool branch first. Until then migration is blocked (Fork branch not active). A single migration can create the canonical child question ledger after activation. In Statoblast’s Fork choices and recovery, prepare the branch, start it after the eight-week fork-choice window closes, and activate it after the recapitalization deadline. Each step is a separate transaction.
  • Multiple children. Each must already have a canonical question ledger. Migrate to each missing ledger in its own call. A token locked by an earlier migration can still migrate to a new child.

To migrate directly, call ShareToken.migrate(fromId, targetOutcomeIndexes) for each source token ID with strictly increasing target outcome indexes.

A child can open a trading pool only if its question ledger returns to Operational before question end. To recover collateral without trading, follow Handle resolution. An eligible complete set or winning share can pay ETH and REP together or REP alone, without a trading pool or auction bid.

Forks and resolution explains why the trading pool behaves this way.
