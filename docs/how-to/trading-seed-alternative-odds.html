How-to guide

Seed alternative conditional odds

Use this guide when you call the trading pool contract (the pair) yourself and want a new trading pool to open at a specific Conditional Yes price rather than 50%.

Before you call initialize

Creating and initializing the trading pool in separate transactions lets someone seed it first. Prefer the router’s createPairAndInitializeWithEth for atomic initialization with deposit and liquidity bounds. The first-market tutorial shows the UI path.

  • The question has not ended, its universe has not forked, and the question ledger is Operational and unresolved.
  • The smaller deposit must exceed MINIMUM_LIQUIDITY (1,000 share base units).

The pair reference lists the remaining preconditions of initialize.

Seed the trading pool

  1. Look up the security pool with securityPoolOf(questionLedger) on the question ledger’s factory. Call the security pool’s purchaseQuote(universeId, questionId, cash). Approve the security pool’s services() to spend the collateral for cash plus the quoted fee, including the resolution premium. Call the security pool’s createCompleteSet(universeId, questionId, cash, recipient, minimumShares, maximumFee) with your address as the recipient. Let q be the Yes share amount minted by this purchase.
  2. Create the trading pool with the factory's createPair(questionLedger), unless it already exists.
  3. Choose the Conditional Yes price p in basis points with 0 < p < 10,000 and compute the deposits:
    • If p ≥ 5,000, deposit all q No and ⌊q × (10,000 − p) / p⌋ Yes.
    • If p < 5,000, deposit all q Yes and ⌊q × p / (10,000 − p)⌋ No.
  4. Approve the trading pool as an operator on the canonical ShareToken with setApprovalForAll; initialize pulls both deposits from the caller.
  5. Call initialize(yesAmount, noAmount, minLiquidity, recipient, deadline) with those deposits. Set minLiquidity to the smaller deposit minus the 1,000 LP base units minted to the lock address. Set deadline to the latest timestamp at which the call may still execute.
  6. Check the result: getReserves() returns your two deposits and tradingStatus() returns Open. If initialize reverted with Already initialized, someone else seeded the trading pool first.

Conditional pricing works through the 70% example and explains why the larger reserve is the side you are betting against.
