Prepare an immutable release

Produce reviewable release evidence before deploying contracts that cannot be paused, upgraded, or rescued administratively.

Freeze the candidate

  1. Choose and record the exact release-candidate commit. Do not create the final signed release tag yet.
  2. Install from the lockfile and initialize generated contract dependencies in a clean checkout with bun install --frozen-lockfile && bun run setup.
  3. Record Bun, Solidity compiler, Foundry, and operating-system versions.
  4. Confirm the worktree is clean before producing artifacts.

Run release validation

Run the commands below separately and stop on the first failure. Record output and a scope-based reason for every skipped category.

bun run ensure-contract-artifacts
bun run tsc
bun run check:shared-dependencies
bun run test:run -- --bail=1
bun run format:check
bun run check
bun run knip
bun run check:generated-clean
bun run ui:build:prod:current
git diff --check

Expected results are a zero exit status, no generated diff, a passing production build, and test output tied to the frozen commit.

Record provenance

  1. Build production contracts and UI from the frozen checkout.
  2. Record artifact hashes, bytecode hashes, compiler settings, deterministic addresses, constructor arguments, and external-token addresses.
  3. Publish the final commit, tag, manifest, validation results, and known limitations together.

Review immutable parameters

Re-evaluate every economic, timing, integer-width, and gas relationship named by assumption A25. A later UI release cannot repair unsafe immutable values.

Release gate

No-go conditions are a dirty worktree, mismatched lockfile, failed or unexplained check, stale generated output, an immutable-parameter change that is unreviewed, unexplained, absent from the economic analysis, or missing corresponding test and documentation updates, an artifact mismatch, or an unreproducible clean-room build. Have a second machine or clean checkout reproduce the hashes before creating the final signed release tag. This is an immutable contract release: deployed contracts cannot be paused, upgraded, or administratively rescued. After deployment, continue with deployment verification.
