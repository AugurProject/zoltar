Escalation Game

The Escalation Game gives a finished Statoblast market a local, REP-backed resolution path before a universe-wide fork is necessary. A report that nobody challenges wins three days after the first deposit opens the game.

For a binary launch question, suppose Yes has 8 REP, No has 5 REP, and Invalid has 2 REP. The median balance, 5 REP, is the game's binding capital: the stake the strongest challenger has committed, and the amount that sets the scheduled deadline. A deposit that raises only the leading Yes balance does not move that deadline; a deposit that raises Invalid above 5 REP raises the median and moves it later.

After the deadline, Yes wins only if it remains the unique strict leader. If two outcomes each reach the non-decision threshold before local finalization, the game records non-decision and the SecurityPool follows the Zoltar fork path. The threshold is half of Zoltar's fork threshold, rounded up, and is fixed when the game opens. A tie is never treated as a local winner.

Any REP holder can deposit from a wallet, except in a game carried across a fork. A vault owner can instead deposit REP that already backs their vault; those deposits must additionally leave the vault and the pool sufficiently backed. Each deposit must meet the start bond, the larger of 1 REP and one ten-millionth of the universe's theoretical REP supply when the pool was deployed, unless it exactly fills an outcome to the non-decision threshold.

Escalation

The first deposit after the question ends opens the game. Each deposit adds to its outcome's cumulative balance; it does not have to exceed the leader. Meanwhile the required support rises along a fixed curve over time. The scheduled deadline estimates when required support will overtake binding capital, so it moves later only when a deposit raises the median balance. Rounding can delay the actual crossing beyond that deadline. A challenger that stops adding REP lets the rising requirement pass its stake, and the leader wins.

How the game ends

The game ends in one of three ways:

  1. Strict local winner. Statoblast finalizes on the unique strict leader only after the scheduled deadline has passed and required support has overtaken binding capital.
  2. Local non-decision. Two outcomes reach the non-decision threshold. Statoblast uses its fork path instead of choosing one locally.
  3. Interruption by another fork. The pool's universe forks on a different question while the game is unresolved, even if its scheduled deadline has passed. Required support freezes at the fork, and the game continues in the child pools instead; see forks and migration. A result already final before the fork stays settled.

Settlement rewards the side that held its ground. Winning deposits get their principal back plus a bonus. The runner-up's stake, the binding capital, pays for it: three fifths becomes the bonus pool and two fifths, the escalation haircut, is burned, unless the fork this game triggered already burned it as the fork haircut. REP staked on a third outcome is forfeited: a local game sweeps it to the SecurityPool, while a game carried across a fork burns it. The bonus is only available on the portion of winning deposits up to the reward-eligible cap, one and a half times binding capital; deposits beyond that cap simply get their principal back. Settlement also compares the universe's current fork threshold, in full, with the non-decision threshold the game fixed when it opened. If the current fork threshold is the lower of the two, every winning withdrawal is multiplied by the current fork threshold divided by that non-decision threshold, which can push the final transfer below principal. The comparison is skipped when the universe forked after the game ended. The EscalationGame reference works one payout through with exact numbers.

Escalation game continuation

When a fork interrupts an unresolved game, Statoblast's SecurityPoolForker restarts it in each child pool as a carried game with the parent's balances and elapsed time. In a child created by a fork on the pool's own question, the outcome is already fixed to that child's outcome, so the game only settles deposits on it. After an unrelated fork, the game resumes and can still be contested, but only with vault-backed deposits. Depositors claim their positions in a child with a Merkle Mountain Range carry proof against the parent's deposit history, so no child copies every deposit onchain.

Design rationale

Augur V2 cancelled active dispute games when a fork began and refunded their participants. Statoblast instead continues active games across the fork so a fork cannot erase the stakes players already put at risk. See the research note Zoltar forks should not cancel escalation games for the historical motivation.
