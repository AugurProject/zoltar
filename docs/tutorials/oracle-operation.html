Inspect an accepted oracle price

Use the deterministic Security pool fixture to connect a settled OpenOracle report to the pool's valid REP/ETH price cache and the operations that consume it. The fixture starts after settlement; callback failure and recovery are covered separately as operational branches.

Open the Oracle view

Serve the UI and open http://localhost:12345/?simulate=1&simScenario=security-pool#/open-oracle. Wait for the Security pool scenario, then open the seeded report in the report browser. Uniswap-backed quoting is unavailable in simulation; the report and cached price are deterministic fixture state.

Checkpoint: at least one seeded report is settled and distributed.

Inspect the coordinator

Return to Will this resolve?, open its funded vault, and inspect the oracle manager. Confirm that the cached price is valid, the seeded report is no longer pending, and no staged operation remains attached to settlement.

Checkpoint: the manager has a valid price and no pending report.

Inspect the report

Compare the report's final token amounts, reporter, settlement time, and distributed state with the manager's cached REP/ETH price. Statoblast uses the accepted price for pool solvency; OpenOracle does not decide the market outcome.

Compare immediate and staged paths

Open a price-sensitive vault action without submitting it. With the fixture's fresh price, the operation can execute immediately after staging; it does not need another report. If the price expires later, the same operation requires report funding or waits beside a pending report. Keep the exercise read-only so the deterministic checkpoint remains valid.

Checkpoint: a fresh cached price changes the execution path but not the downstream pool safety checks.

What you learned

You connected a settled report, the cached price, and the immediate operation path without inventing a pending or rejected callback. Use the recovery guide for the distinct failure branches or continue to the integration explanation.
